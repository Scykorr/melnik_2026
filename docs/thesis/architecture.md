# Материалы к пояснительной записке

Название: «Разработка автоматизированной системы мониторинга протестной активности населения для подготовки ИАМ «Регион»».

## AS-IS / TO-BE

Ручной контур и контур с системой описаны в `docs/as_is_to_be.md`.

## Компоненты

`config` — настройки, HTTP и Celery. Приложения: учётные записи, территории и темы, источники, загрузка, документы, события, аналитика, отчёты, аудит, испытания. Интерфейс — шаблоны Django, HTMX и Alpine. API — `/api/v1/`.

## ER, укрупнённо

Территория и тема справочные. Источник ссылается на территорию. Документ принадлежит источнику. Событие связано с документами через `EventDocument` и имеет статус, оценку и историю решений. Дневная метрика уникальна для территории, даты и версии методики. Отчёт хранит версию и после утверждения не меняется. Журнал хранит действие, а не полный текст.

## Аналоги

Сравнение вынесено в `docs/thesis/analogues.md`. Чужие показатели качества сюда не переносятся как собственные.

## Матрица требований

См. `docs/traceability.md` и `docs/thesis/indicators.md`.

## Как повторить испытания

1. Поднять стенд по `docs/РУКОВОДСТВО_ПОЛЬЗОВАТЕЛЯ.md`.
2. Импортировать внешний эталон: `python manage.py import_gold путь.csv --dataset ИМЯ`.
3. Посчитать дедупликацию: `python manage.py evaluate_dedup --dataset ИМЯ --method tfidf --split test`.
4. Внести сессии AS-IS и TO-BE в разделе «Испытания».
5. Выгрузить отчёт: `python manage.py export_evaluation_report`.

Без этих шагов в отчёте остаётся «не измерено».
